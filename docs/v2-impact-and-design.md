# V1.0 到 V2.0 影响分析与设计

## 范围决策

2026-10-09 用户明确选择：仅实现已确认部分，未明确流程暂不启用。候补排序、待审核占名额、自动递补、审核后分配名额、账号停用后登录与操作限制均未获业务确认，不启用推测规则。

V2.0 是 V1.0 原型上的有限范围迭代，不宣称完整候补或审核报名闭环已完成。原始 ZIP 导入为 Git 标签 v1.0-baseline；保留 React、TypeScript、vinext、已有样式与组件、浏览器本地存储。

## 数据变化

- AppState.version 从 1 升为 2。
- User.role 扩展 admin；managementStatus 增加 enabled/disabled，仅记录管理标记。
- Activity 增加 eligibilityText 与 requiresReview。空条件沿用 V1 普通报名；有条件的新报名入口暂不启用。
- Registration.status 扩展 waitlisted、pending；新增 reviewDecision（pending/approved/rejected）、reviewedAt、reviewedBy。资格通过与正式参加是独立概念；审核不修改名额状态。
- V1 active/cancelled 原样保留；空值默认不审核。没有证据将旧报名自动转换成候补或申请。
- 新安装的演示数据使用相对未来日期，明确标注预置候补与待确认申请，避免把测试夹具冒充真实报名流程。

## 业务流程

普通活动：学生登录 → 浏览已发布活动 → 状态/时间/重复/容量校验 → 正式报名 → 开始前可取消。遇到已有候补的活动，暂停新的报名和取消名额变动，避免无规则地绕过队列或释放后错误分配。

有条件活动：显示条件和新申请暂停说明 → 教师查看预置/已有申请 → 记录通过或拒绝 → 学生查看结果。通过后仍显示待安排，不能自动显示报名成功。开始/取消后不处理申请，属于限制未确认流程的实现边界。

管理员：查看账号 → 标记停用/恢复 → 查看状态；历史数据保留，界面说明登录限制未启用。查看全平台活动只读，不能代办报名。

候补：仅展示已有候补状态；不创建队列、不假定时间排序、不递补、不退出或重入。US-01 与 US-05 完整验收挂起，US-04 只验收已有申请资格结果，US-07 只验收状态记录。

## 兼容性与测试影响

需要测试角色越权、拒绝后不得重新变更、资格通过不占用新正式名额、候补保持不变、取消活动显示、V1 迁移幂等与损坏数据保护，并回归原有 8 个领域场景。迁移保留旧 localStorage 键作为备份，不覆盖用户原始 ZIP。

登录和权限仍是本地教学原型，不是生产服务端认证；本轮没有已确认的跨设备协作需求，因此不另建后端。跨标签页读取最新存储可同步展示，但不宣称具备服务端并发事务能力。
